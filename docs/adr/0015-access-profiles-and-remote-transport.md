# ADR 0015: Access profiles

- **Status:** Accepted
- **Date:** 2026-08-31
- **Updated:** 2026-08-31 (profile names `trusted` / `shared`; remote access out of MVP scope)

## Context

Flixbox targets home LAN Docker installs. ADR 0005 defaulted *arr to `AuthenticationMethod=External` and `AuthenticationRequired=DisabledForLocalAddresses` so `./bin/flixbox configure` could wire apps without browser wizards. That treats all RFC1918 clients (including roommates on `192.168.x.x`) as trusted for Radarr/Sonarr/Prowlarr WebUI — acceptable for **`trusted`**, wrong for **`shared`**.

**Gluetun (`FLIXBOX_MODE=vpn`) is torrent egress only** — not remote UI access (ADR 0002).

**Remote access** (phone on cellular, stack from outside the home) is **not in MVP scope** and has **no `.env` switch** until a design is accepted (operator VPN, Caddy hardening, etc.).

## Decision

### Access profiles

| Profile | `FLIXBOX_ACCESS_PROFILE` | *arr auth | Typical home |
| --- | --- | --- | --- |
| **Trusted LAN** (default) | `trusted` | `External` + `DisabledForLocalAddresses` | One operator; everyone on Wi‑Fi trusted |
| **Shared LAN** | `shared` | `Forms` + `Enabled` | Roommates; block casual *arr access |

**Automation contract (unchanged):** `init` pre-seeds API keys; Compose passes `*__AUTH__APIKEY`; `configure` and inter-container calls use `X-Api-Key`. UI login mode does **not** replace API keys.

**`shared` credentials:** `FLIXBOX_ARR_UI_USER` / `FLIXBOX_ARR_UI_PASSWORD` in `.env` (generated by `init` when empty). Used for human browser login to *arr UIs. Distinct from API keys.

**Consumer apps:** Jellyfin and Seerr keep their own user accounts (ADR 0004). Use separate Jellyfin users for household members; do not share admin passwords.

### qBittorrent (all profiles)

- **Auth subnet whitelist** stays **`172.30.42.0/24` only** (Docker peers — ADR 0008). Never whitelist home `192.168.0.0/16`.
- From the **host** (`127.0.0.1`), WebUI may skip password (Docker gateway path).
- From **LAN** (`192.168.x.x`), WebUI **must** require `QBITTORRENT_PASSWORD`.
- Stack peers (Decluttarr, *arr) use API key or credentials over Docker network.

### Roadmap (follow-ups)

| Phase | Scope | Status |
| --- | --- | --- |
| 1 | Profiles `trusted` / `shared`, compose env, `init`, docs | Done |
| 2 | Optional `127.0.0.1` bind for admin ports in `shared`; unpublish Byparr | Future |
| 3 | Remote / WAN ingress (if accepted): Caddy, TLS, auth | Future — not designed |

## Consequences

- ADR 0005 default auth wording applies to profile **`trusted`** only; superseded in part by this ADR for `shared`.
- ADR 0008 qBit whitelist semantics unchanged; inter-container automation only.
- Changing `FLIXBOX_ACCESS_PROFILE` requires `./bin/flixbox init --non-interactive` and recreating *arr containers.
- **`configure` remains valid** for both profiles (API key to `127.0.0.1`).
- IPv6 global clients on LAN may still see *arr login prompts even in `trusted` (Servarr limitation).
